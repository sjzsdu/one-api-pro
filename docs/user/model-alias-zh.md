# 模型别名与模型池

在「设置 → 个人 → 模型别名与模型池」配置个人别名。超级管理员可切换到「全局别名」发布所有用户可见的模型池；「全局别名」入口仅超级管理员可见，管理员和普通用户只能配置个人别名。已有的超级管理员个人别名不会自动公开。

一个别名最多包含 **8 个**不同的具体模型，各设置 1–1000 的权重。新会话按权重随机选择；这是**会话分配比例**，不是 Token 或采购金额的精确比例，也不会自动读取供应商采购额度。单候选的旧配置继续有效。

真实可用模型名称优先，其次为个人别名，最后为全局别名。个人同名配置覆盖全局配置；个人配置失效时不会悄悄退回全局。

## 调用

业务继续发送别名，并为一个对话始终传相同的标识：

```http
POST /v1/chat/completions
Authorization: Bearer sk-…
Content-Type: application/json
X-Session-ID: conversation-123

{"model":"chat-tool","messages":[{"role":"user","content":"你好"}]}
```

`X-Session-ID` 最多 128 字节。不同账号、别名和个人/全局配置的会话相互隔离。未提供标识时，自动对结构化消息历史做最长前缀匹配；命中后沿用原会话，未匹配时才按权重分配。

会话绑定空闲有效期默认 3600 秒，可配置 60–86400 秒；成功调用刷新有效期。Redis 模式使用共享原子绑定；不启用 Redis 时使用有界进程内缓存，多进程之间不会共享会话绑定。

## 不修改客户端的自动识别

对持续携带完整消息历史的 Chat Completions、Messages 和 Responses 客户端，无需新增请求头。路由顺序是：显式 `X-Session-ID` → 最长已有消息前缀 → 加权分配。显式会话不读取或写入自动前缀索引，两者相互隔离。

匹配针对解析后的消息结构，JSON 对象字段顺序和空白不影响身份；数组顺序、角色、工具调用、媒体内容及工具定义等提示上下文保持区分。Responses 使用原始结构化 `input`，不先将媒体或工具项压缩成纯文本。`stream`、`temperature`、`max_tokens` 等本轮生成选项不参与消息身份。

只有累计至少 **32 个非空白用户文本字符**的消息前缀才参与自动识别；系统提示、工具描述和媒体数据不用于凑长度。因此，共同的长系统提示加一句“你好”不会把不同对话绑在一起。缺少足够历史、未命中、历史截断或压缩时会重新分配。完全相同的长前缀仍可能被视为同一会话，自动识别不能替代明确的对话 ID。

前缀索引只保存哈希、过期时间和会话路由引用，不保存消息正文；故障切到备用模型后，旧前缀也通过相同引用沿用新模型。每个账号/别名/个人或全局范围/协议最多保留 1024 条记录，每次最多查询最近 128 个合格消息边界，TTL 沿用会话配置。本地索引另外限制为 256 个命名空间、8192 条总记录；Redis 模式共享索引，未启用 Redis 的多个进程不共享自动识别结果。

设置页测试弹窗仍发送简短测试消息，清空会话 ID 不能验证自动历史匹配；该功能应通过持续追加完整历史的实际对话验证。

同一会话尽量固定到同一模型及成功渠道，有利于复用供应商提示词缓存，但**不能保证缓存命中**。缓存还依赖相同的提示词前缀、工具定义、供应商的缓存范围与有效期。

## 权限与价格

全局别名可以作为模型加入令牌白名单；其候选仍必须属于调用者当前分组。令牌也可只允许某个具体候选，此时仅该候选可用。个人别名始终要求目标模型权限，不能利用与全局别名同名的个人配置继承别名授权。

每次请求重新过滤分组、令牌与已知工具/视觉/上下文能力限制；未知能力不假定已验证支持。删除候选或撤销权限后，旧会话会重新选择仍可用的候选。费用与套餐按最终实际模型重新计算，日志同时保留业务别名和实际上游模型。

## 故障切换

可启用池内故障切换。连接失败、超时、429、529 和上游 5xx 可触发有限重试：先尝试同模型其他健康渠道，再选择池内未尝试过的模型。失败尝试先同步归还预扣额度；成功尝试按其自身定价与套餐结算。参数、权限、余额或退款失败不会触发跨模型重试。

候选耗尽后冷却 30 秒，冷却按分组及模型池隔离。全部候选冷却时返回可重试的 HTTP 503。切换成功后，同会话继续使用新模型，不因为原模型恢复而来回跳转。每个请求最多尝试 8 个模型，每个模型渠道重试有上限。

任何响应数据已经输出或被协议转换器消费后，不再透明重试或追加错误 JSON。多模型池首版支持 JSON Chat Completions、Completions、Claude Messages 和 Responses；其他格式保留单目标别名支持。`previous_response_id`、`conversation` 等供应商会话引用无法由当前 Responses 转换器安全迁移，因此别名池会明确拒绝，要求发送完整聊天历史。

## 管理接口

| 用途 | 接口 |
| --- | --- |
| 个人配置 | `GET/PUT /api/user/model_aliases` |
| 当前用户可用配置 | `GET /api/user/model_aliases/effective` |
| 超级管理员全局配置 | `GET/PUT /api/model_alias/global` |
| 超级管理员全局候选 | `GET /api/model_alias/global/targets` |

```json
{
  "aliases": [{
    "alias": "chat-tool",
    "targets": [{"model": "deepseek", "weight": 3}, {"model": "glm", "weight": 1}],
    "failover_enabled": true,
    "session_ttl_seconds": 3600
  }]
}
```

旧 `target_model` 字段仍兼容；提供 `targets` 时以后者为准，响应中的 `target_model` 为第一候选。
