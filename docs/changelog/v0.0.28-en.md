### ✨ New Features

- **Dual-push CI images**: `release-docker.yml` publishes to both `ghcr.io/<repository>` and `sjzsdu/one-api-pro` for `linux/amd64` + `linux/arm64`, keeping semver tags and `latest`; a `v0.0.28` image tag matching the git tag is also published.
- **`INITIAL_ROOT_PASSWORD`**: seeds the initial root password from this environment variable.
- **Registration switches as env vars**: `REGISTER_ENABLED` / `PASSWORD_REGISTER_ENABLED` still default to `true`; once explicitly set they take precedence, and database options can no longer re-enable them.
- **`SESSION_SECRET` startup warning**: logs a WARN when unset, noting that sessions are invalidated on every restart.
- **`make docker-build`**: builds the frontend before the image, so `//go:embed` never picks up an empty directory.

### 🔒 Security

- Removed the hard-coded root `123456` password: without `INITIAL_ROOT_PASSWORD`, a one-time cryptographically random password is generated with `crypto/rand` and printed once at startup.
- Registration switches cannot be rolled back by the database: env-managed keys skip database writes and are re-applied after every load.
- `.dockerignore` still excludes `.env` / `.env.*`.

### 🔧 Build & Release

- Fixed `CGO_ENABLED=0` cross-compilation: ONNX embedding is gated by a build tag with a pure-Go stub, so release binaries and images no longer need cgo.
- Fixed the Windows release binary: `Daemonize()` is split into `daemon_unix.go` / `daemon_windows.go`.
- `release.yml` now uses Go 1.25, matching `go.mod`.

### ⚠️ Upgrade notes

- The root password change affects fresh deployments only (empty user table): it is no longer `123456`; take the random password from the startup log and change it immediately.
- For production, pin `SESSION_SECRET` and `INITIAL_ROOT_PASSWORD`, and set `REGISTER_ENABLED=false` plus `PASSWORD_REGISTER_ENABLED=false`.
- Configure `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN` in the repository, or the `release-docker` workflow fails deliberately.
- `CGO_ENABLED=0` binaries have no local ONNX embedding; `MODEL_ROUTER_STRATEGY=cluster` requires `EMBEDDING_PROVIDER=api`.
- No schema change and no migration script.
