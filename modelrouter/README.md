# Embedding router

Set `MODEL_ROUTER_STRATEGY=embedding` to enable semantic routing. The default
router remains `random`.

Local ONNX configuration:

```env
EMBEDDING_PROVIDER=onnx
EMBEDDING_MODEL=jina-v2-code
EMBEDDING_MODEL_PATH=/models/model.onnx
EMBEDDING_TOKENIZER_PATH=/models/tokenizer.json
ONNXRUNTIME_LIBRARY=/opt/onnxruntime/lib/libonnxruntime.so
CLUSTER_TOPP=4
ARTIFACTS_PATH=./modelrouter/artifacts
```

Both Jina v2 Code's WordPiece and Qwen3's BPE are loaded from HuggingFace
`tokenizer.json` files. A lightweight `WordPieceTokenizer` and the extensible
`Tokenizer`/`TokenizerFunc` interfaces are also available to Go callers. The
ONNX runner supports either pooled `[batch, dimension]` output or token-level
`[batch, sequence, dimension]` output, and reuses one native session.

For an OpenAI-compatible service, including DashScope's compatible endpoint:

```env
EMBEDDING_PROVIDER=api
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_API_ENDPOINT=https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings
EMBEDDING_API_KEY=...
```

When provider is `onnx` and API settings are also present, failure to initialize
the local runtime falls back to the API. A runtime inference error also falls
back through `FallbackEmbedder`.

The checked-in artifacts are a small schema-valid starter set using an
8-dimensional Matryoshka projection. Replace them with centroids, per-cluster
quality means, rankings, and normalized cost/latency metadata generated by the
offline evaluation pipeline before production use.
