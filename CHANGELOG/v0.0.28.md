# v0.0.28 — 2026-11-14

> 本版本让 one-api-pro 可以由 deploy 仓库自托管上线：CI 同时推送 Docker Hub 与 GHCR 双架构镜像，并补齐公网暴露前必须的安全加固（初始 root 密码、注册开关环境变量优先、会话密钥告警）。

## 中文

### ✨ 新增功能

- **CI 双推镜像**：`release-docker.yml` 现在同时推送 `ghcr.io/<repository>` 与 `sjzsdu/one-api-pro`，`linux/amd64` + `linux/arm64` 双架构、semver 标签与 `latest` 保持不变。新增 `docker/login-action@v3` 登录 `docker.io`，凭据取自仓库 Secrets `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN`（Access Token）。
- **凭据缺失快速失败**：新增 "Verify Docker Hub credentials" 步骤，Secrets 未配置时直接报错并明确拒绝退回只推 GHCR，避免"以为发到了 Docker Hub、其实只发了 GHCR"的静默降级。
- **`INITIAL_ROOT_PASSWORD`**：首次启动时用该环境变量的值创建 root 账号密码。
- **注册开关环境变量**：新增 `REGISTER_ENABLED` / `PASSWORD_REGISTER_ENABLED`，默认仍为 `true`（兼容本地开发）；显式设置后由环境变量接管，`InitOptionMap()`、`loadOptionsFromDatabase()`、`SyncOptions()` 以及后台 `UpdateOption()` 都无法用数据库里的 option 值把它覆盖回去。
- **`SESSION_SECRET` 启动告警**：未设置时打一条 WARN，提示重启会导致所有会话失效；默认值语义不变（仍为启动时随机 UUID）。
- **`make docker-build`**：先构建 `web/build/default-pro` 再执行 `docker build`，避免本地裸构建因为 `//go:embed all:web/build` 拿到空目录而失败或前端空白。Dockerfile 的多阶段结构未改动，镜像内仍不运行 npm。

### 🔒 安全

- **移除写死的 root 密码**：此前 `CreateRootAccountIfNeed()` 在任何环境都用 `123456` 建号，公网暴露等于任何人可登录后台。现在未设置 `INITIAL_ROOT_PASSWORD` 时用 `crypto/rand` 生成密码学安全的随机密码，并在启动日志打印一次（仅此一次，需立即保存并修改）。`INITIAL_ROOT_TOKEN` / `INITIAL_ROOT_ACCESS_TOKEN` 语义不变。
- **注册开关不可被数据库回滚**：`model/option.go` 对受环境变量接管的 key 跳过数据库写入，并在每次加载后重新应用环境变量值。此前只加 env 默认值会在 `SyncOptions()` 同步后被 DB 里的旧 option 重新打开注册。
- **`.dockerignore` 继续排除 `.env` / `.env.*`**：本次未改动该规则，构建上下文不会携带真实凭据。

### 🔧 构建与发布

- `release.yml` 的 `actions/setup-go` 版本由 `1.22` 提升为 `1.25`，与 `go.mod` 的 `go 1.25.0` 对齐，避免 `v*` tag 触发的 Release job 依赖运行时下载 toolchain 而失败。
- **修复 `CGO_ENABLED=0` 交叉编译失败**：`modelrouter/embedder_onnx.go` 原先无条件引入纯 cgo 包 `github.com/yalue/onnxruntime_go`，导致 `release.yml` 的 5 个平台二进制与 `Dockerfile` 的 `CGO_ENABLED=0 go build` 全部报 `build constraints exclude all Go files`。现在该文件只在 `//go:build cgo` 下编译，新增 `modelrouter/embedder_onnx_stub.go` 在 `!cgo` 下提供同名纯 Go 占位实现并返回明确错误。发布二进制与镜像不再依赖 cgo / ONNX Runtime；本地 `CGO_ENABLED=1` 构建行为完全不变。
- **修复 Windows 发布二进制编译失败**：`common/daemon.go` 原先直接用 `syscall.ForkExec` / `SysProcAttr.Setsid` 实现后台模式，Windows 交叉编译报 `undefined: syscall.ForkExec`。现在把 `Daemonize()` 按平台拆到 `daemon_unix.go`（`!windows`，原逻辑不变）与 `daemon_windows.go`（`windows`，返回明确错误），`common/daemon.go` 保留平台无关逻辑与单测。`release.yml` 的 5 个目标现可全部编译。
- 新增 `CHANGELOG/v0.0.28.md`，满足两个 workflow 对 `CHANGELOG/<tag>.md` 的强制校验；`VERSION` 同步为 `0.0.28`。
- 使用干净 semver tag `v0.0.28`（无 `-fork` 预发布后缀），`latest=auto` 才会为该镜像打上 `latest`。

### 📚 文档

- `.env.example` 与 `README.md` 环境变量清单补齐 `INITIAL_ROOT_PASSWORD`、`REGISTER_ENABLED`、`PASSWORD_REGISTER_ENABLED`，并修正文档中 `root / 123456` 的默认账号说明。

### ⚠️ 升级注意事项（Behavior Change）

- **root 密码行为变更（重要）**：仅当数据库中不存在任何用户（全新部署首次启动）时生效。此时若未设置 `INITIAL_ROOT_PASSWORD`，root 密码不再固定为 `123456`，而是日志里的一次性随机密码；请从启动日志取回并立即在后台修改。已有用户表不受影响，存量 root 密码不会被重置。
- 生产部署建议同时固定：`SESSION_SECRET`（否则每次重启会话失效）、`INITIAL_ROOT_PASSWORD`（放在 deploy 侧 `.env.secrets`）、`REGISTER_ENABLED=false`、`PASSWORD_REGISTER_ENABLED=false`。
- 注册开关被环境变量接管时，后台「系统设置」里对应开关的修改不会生效（仍会写入数据库，但运行时以环境变量为准）；如需恢复后台控制，删除对应环境变量并重启。
- 发布前必须在 `sjzsdu/one-api-pro` 仓库配置 `DOCKERHUB_USERNAME` 与 `DOCKERHUB_TOKEN`，否则 `release-docker` workflow 会主动失败。
- **无 cgo 二进制的 cluster 路由**：发布镜像与 GitHub Release 二进制均以 `CGO_ENABLED=0` 构建，其中本地 ONNX embedding 不可用。若把 `MODEL_ROUTER_STRATEGY` 设为 `cluster` 且未配置 `EMBEDDING_PROVIDER=api`，启动时会得到明确错误 `ONNX embedder requires a cgo-enabled build`。默认 `MODEL_ROUTER_STRATEGY=random` 不受影响，同时也避免了国内网络下自动下载 ONNX 模型/artifact。需要本地 ONNX 请用 `CGO_ENABLED=1` 自行编译，或设置 `EMBEDDING_PROVIDER=api` 走外部 embedding 接口。
- 无数据库结构变更，无需执行迁移脚本；`SQL_DSN=postgres://...` 分支未改动，不引入 MySQL / Redis 硬依赖。

## English

### ✨ New Features

- **Dual-push CI images**: `release-docker.yml` now publishes to both `ghcr.io/<repository>` and `sjzsdu/one-api-pro` for `linux/amd64` + `linux/arm64`, keeping semver tags and `latest`. A new `docker/login-action@v3` step logs into `docker.io` using the repository Secrets `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN` (an Access Token).
- **Fail fast on missing credentials**: the new "Verify Docker Hub credentials" step fails explicitly when the Secrets are absent and refuses to degrade to a GHCR-only push.
- **`INITIAL_ROOT_PASSWORD`**: seeds the initial root account password from this environment variable.
- **Registration switches as env vars**: `REGISTER_ENABLED` / `PASSWORD_REGISTER_ENABLED` default to `true` (unchanged local-development behaviour). Once explicitly set, they take precedence: `InitOptionMap()`, `loadOptionsFromDatabase()`, `SyncOptions()` and the admin `UpdateOption()` path can no longer overwrite them from database options.
- **`SESSION_SECRET` startup warning**: logs a WARN when unset, explaining that sessions are invalidated on every restart. Default semantics are unchanged (random UUID per startup).
- **`make docker-build`**: builds `web/build/default-pro` before `docker build`, so a bare local build never hits an empty `//go:embed all:web/build` directory. The Dockerfile multi-stage layout is untouched and npm still never runs inside the image.

### 🔒 Security

- **Removed the hard-coded root password**: `CreateRootAccountIfNeed()` previously created `root` with `123456` in every environment, which made a public deployment trivially accessible. When `INITIAL_ROOT_PASSWORD` is unset, a cryptographically secure random password is now generated with `crypto/rand` and printed once to the startup log. `INITIAL_ROOT_TOKEN` / `INITIAL_ROOT_ACCESS_TOKEN` semantics are unchanged.
- **Registration switches cannot be rolled back by the database**: `model/option.go` skips env-managed keys and re-applies env values after each load. Previously an env-only default was silently re-enabled by a stale DB option during `SyncOptions()`.
- **`.dockerignore` still excludes `.env` / `.env.*`**: unchanged, so real credentials never enter the build context.

### 🔧 Build & Release

- `release.yml` now uses `actions/setup-go` with Go `1.25` (matching `go.mod`), so the `v*`-triggered Release job no longer depends on a runtime toolchain download.
- **Fixed the `CGO_ENABLED=0` cross-compilation failure**: `modelrouter/embedder_onnx.go` unconditionally imported the cgo-only `github.com/yalue/onnxruntime_go` package, so all five release binaries and the `Dockerfile` build failed with `build constraints exclude all Go files`. The file is now gated by `//go:build cgo`, and a new `modelrouter/embedder_onnx_stub.go` provides matching pure-Go symbols that return a clear error when cgo is disabled. Release binaries and images no longer need cgo / ONNX Runtime; local `CGO_ENABLED=1` builds are unchanged.
- **Fixed the Windows release binary**: `common/daemon.go` used `syscall.ForkExec` / `SysProcAttr.Setsid` directly, which fails on Windows with `undefined: syscall.ForkExec`. `Daemonize()` is now split into `daemon_unix.go` (`!windows`, unchanged behaviour) and `daemon_windows.go` (`windows`, explicit error); platform-independent logic and tests stay in `common/daemon.go`. All five `release.yml` targets now compile.
- Added `CHANGELOG/v0.0.28.md` to satisfy the mandatory `CHANGELOG/<tag>.md` check in both workflows; `VERSION` bumped to `0.0.28`.
- Uses the clean semver tag `v0.0.28` (no `-fork` prerelease suffix) so `latest=auto` produces a `latest` tag.

### 📚 Documentation

- `.env.example` and the README env-var list now document `INITIAL_ROOT_PASSWORD`, `REGISTER_ENABLED` and `PASSWORD_REGISTER_ENABLED`; stale `root / 123456` instructions were corrected.

### ⚠️ Upgrade Notes (Behavior Change)

- **Root password behaviour changed (important)**: applies only on a fresh database with no users. Without `INITIAL_ROOT_PASSWORD`, the root password is no longer `123456` but a one-time random password printed in the startup log — save it and change it immediately. Existing user tables are untouched and existing root passwords are never reset.
- For production, pin `SESSION_SECRET`, set `INITIAL_ROOT_PASSWORD` (in the deploy-side `.env.secrets`), and set `REGISTER_ENABLED=false` plus `PASSWORD_REGISTER_ENABLED=false`.
- While a switch is env-managed, changes made in the admin console are persisted to the database but do not take effect at runtime. Remove the env var and restart to hand control back to the console.
- `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` must be configured on the `sjzsdu/one-api-pro` repository before tagging, otherwise the `release-docker` workflow fails on purpose.
- **Cluster routing in cgo-free binaries**: release images and GitHub Release binaries are built with `CGO_ENABLED=0`, so local ONNX embeddings are unavailable. Setting `MODEL_ROUTER_STRATEGY=cluster` without `EMBEDDING_PROVIDER=api` now fails fast with `ONNX embedder requires a cgo-enabled build`. The default `MODEL_ROUTER_STRATEGY=random` is unaffected, and automatic ONNX model/artifact downloads are avoided on restricted networks. Build locally with `CGO_ENABLED=1` or set `EMBEDDING_PROVIDER=api` to use local ONNX.
- No database schema changes and no migration script required. The `SQL_DSN=postgres://...` path is untouched; no MySQL / Redis hard dependency was introduced.
